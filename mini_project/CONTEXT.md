> 이 문서의 숫자는 **추정이 아니라 직접 잰 값**입니다 — 설계 때(2026-11-06) 잰 것은 부록 A ~ C,

### 1교시 «PDF 파싱 난점» — 이 문서에서 실제로 나온 것

`PyPDFLoader` 로 두 PDF 를 직접 적재해 확인했습니다.

| 난점 | 실제 모습 | 대응 |
|---|---|---|
| 머리말 · 쪽 번호 | 가이드라인 **36쪽 중 34쪽**에 «재활용품 분리배출 N» / 사례집 **52쪽 중 41쪽**에 «2026년도 내 손안의 분리배출 앱 Q&A 사례 100» | 정규식으로 제거 (10주차 `build_index.py` 의 `HEADER` 방식) |
| **원본 오탈자** | 사례집 머리말 50회 중 **35회가 «2026넌도»**(년→넌) | 정규식을 `2026[넌년]도` 로 — **한 가지 모양만 지우면 35쪽에 잡음이 남습니다** |
| 다단 레이아웃 | 품목사전 28쪽의 초성 구역이 **«나 → 가 → 다»** 순으로 뽑힘 (2단 배치라 오른쪽 단이 먼저 읽힘) | 품목사전은 **«품목 → 배출방법» 한 줄 = 한 항목**으로 따로 파싱 (순서가 섞여도 항목은 안 깨짐) |
| 표 | 과태료 기준표(9장)가 «5 5 5 / 20 20 20» 숫자 나열로 풀림 | **범위 밖** — 과태료 질문은 받지 않음 |
| 빈 쪽 · 표지 | 가이드라인 마지막 쪽 0자, 표지 15자 | 구역 지도에 없는 쪽은 버림 · 본문 청크만 30자 미만 버림 |
| 그림 속 글자 | «분리배출 핵심 4가지(비운다·헹군다·분리한다·섞지않는다)» 가 단어 조각으로 흩어짐 | 본문 다른 쪽에 같은 내용이 글로 있어 그대로 둠 |

> 📌 **«쓰레기를 넣으면 쓰레기가 나온다»** — 머리말 정규식이 오탈자 «넌» 을 놓쳤다면,
> 사례집 청크 35개에 «2026넌도 내 손안의 분리배출 앱 Q&A 사례 100» 이 섞여 **모든 청크가 서로 비슷해 보였을 것**입니다.

## 분할 · 메타데이터 설계 ★ (2교시 2절 반영)

### 분할 방식: **문서별 구조 기반 → 긴 것만 재귀** (2단 구성)

두 문서의 «의미 단위» 가 서로 다르므로 **하나의 splitter 로 통일하지 않습니다.**

| 구역 | 1단 — 구조로 나누는 단위 (C) | 2단 — 재귀 (B) | 이유 |
|---|---|---|---|
| 사례집 Q&A 100건 | **Q&A 1건 = 1청크** (날짜 · 사례 번호로 건을 잡고, 본문은 **품목 이름으로 짝지음**) | 안 탐 (평균 **151자** · 최대 423자) | 질문 1개 = 사례 1건. 두 건이 한 청크에 섞이면 «선글라스» 질문에 «축구화» 답이 근거로 들어감 |
| 가이드라인 FAQ 36문항 | **«Q :» 1개 = 1청크** | 안 탐 (평균 106자 · 최대 218자) | 위와 같음 |
| 가이드라인 품목사전 | **품목 1줄 = 1청크** («나무젓가락 / 종량제봉투로 배출») | 안 탐 | 한 줄짜리 정답. 다단 때문에 쪽 단위로 자르면 «가» 와 «나» 가 뒤섞임 |
| 가이드라인 본문 1~7장 | **쪽 단위** + 목차로 만든 `section`(«3.1 종이류» 등) | 400자 | 그림 글자 조각 때문에 소절 제목을 규칙으로 못 잡아, 쪽으로 자르고 소절 이름은 메타데이터로 |

**구현 결과**(`python build_index.py --check` · 15항목 통과) — 합계 **456청크**

| 구역 | 청크 | 평균 | 최대 |
|---|---|---|---|
| 사례집 Q&A | 100 | 151자 | 423자 |
| FAQ | 36 | 106자 | 218자 |
| 품목사전 | 282 (이웃 항목과 섞인 4건 제외) | 20자 | 65자 |
| 가이드라인 본문 | 38 | 295자 | 399자 |

- ⚠️ 사례집은 2단 배치라 **날짜 · 품목 라벨과 Q · A 본문의 순서가 쪽 안에서 다릅니다**. 순서대로 짝지으면 100건 중 **24건이 틀려**,
  쪽마다 «품목 이름과 질문이 가장 많이 겹치는 짝» 을 고르도록 했습니다(장별 건수 · 번호 1..n 을 `--check` 가 대조).

아래 표는 **설계 때의 시험 구현** 기록입니다(구현에서 규칙이 바뀌어 숫자가 다름 — 위 표가 최종).

**구조 분할을 실제 PDF 에 돌려 본 결과**(정규식 시험 구현 · 2026-11-06)

| 구역 | 잡힌 단위 수 | 상태 | 남은 문제 → 대응 |
|---|---|---|---|
| 사례집 Q&A | 날짜 **100개 = 100건** ✅ | 건수는 정확 | 2단 배치라 **날짜·품목 라벨(«탁상달력 1»)이 Q&A 뒤에 오는 쪽과 앞에 오는 쪽이 섞임** → 라벨이 이웃 단위에 붙음. 라벨 위치를 쪽마다 판별하는 규칙 + `build_index.py --show` 로 100건 눈 확인 |
| 가이드라인 FAQ | **36문항** ✅ | 평균 113자 · 최대 234자 — 2단(재귀)이 필요 없음 | 없음 |
| 품목사전 | 한 줄 항목 **243개** | 대부분 정상 («나사(못) 고철로 배출») | 품목명이 두 줄인 항목은 앞부분이 잘림(«(MP3등) 폐가전제품으로…» ← «휴대용 플레이어») → **앞 줄과 잇는 규칙** (10주차 `clean()` 의 «끊긴 줄 잇기» 와 같은 문제) |

- 구조로 못 자른 나머지는 **재귀 400/40 으로 떨어뜨립니다**(fallback). 구조 분할이 일부 실패해도 인덱스는 만들어집니다.
- 3교시 실습 2 의 결론 — **«검색 품질의 상한은 분할이 정한다»** — 를 그대로 적용합니다.
  고정 크기로 자르면 사례집 한 청크(400자)에 **Q&A 2~3건이 섞여** 질문과 덜 닮아 보입니다(실습 2 의 «A 고정» 과 같은 현상).
- 구조 분할은 `MarkdownHeaderTextSplitter` 대신 **정규식 파서**로 합니다 — PDF 라 `#` 헤더가 없기 때문입니다
  (2교시 «구조 기반은 구조가 있어야 쓴다» → 구조를 **직접 찾아서** 씁니다).

### `chunk_size` / `chunk_overlap`: **400 / 40** (오버랩 10%)

- 학칙(500/50)보다 작게 잡은 이유: 분리배출 답은 **짧습니다**. 사례 1건 평균 150자, 품목사전 1줄 20~40자.
  500 으로 잡으면 재질 소절이 «종이류 + 종이팩» 처럼 두 재질을 한 청크에 담게 됩니다.
- 2단(재귀)은 400자를 넘는 **본문 소절에만** 걸립니다. Q&A · 품목은 구조 단위 그대로 둡니다.
- 비교 기준(실측): 재귀 400/40 만으로 자르면 **181청크 · 평균 294자**(전 쪽). 구조 우선과 **같은 쪽 · 같은 정리**로 맞춘 재귀 135청크와 비교하니
  검색 Top-3 **19 → 23 / 24** (부록 D-1).
- «30자 미만은 버림» 은 **본문 청크에만** 겁니다 — 품목사전 항목은 평균 20자라 이 규칙을 걸면 대부분 사라집니다.

### 심을 메타데이터

| 키 | 예시 | 타입 | 용도 (실제로 쓰인 곳) |
|---|---|---|---|
| `source` | `분리배출_QA사례100_2026.pdf` | str | 출처 표기 (짧은 이름 «사례집» · «가이드라인») |
| `page` | `31` | int | **출처 표기** — PDF 에서만 얻을 수 있음 · 자르고 나면 복원 불가 ★ |
| `year` | `2026` | **int** | ★ **최신 우선** — `year >= 2020` 이면 거리에서 0.09 를 빼 줌(필터가 아니라 보정 — 2018 에만 있는 품목을 잃지 않게) · 출처에 연도 · 연도 섞임 안내 |
| `doc_type` | `guideline` / `qa_case` / `faq` / `item_dict` | str | 구역별 통계 · 출처 문구(FAQ → «앱 FAQ») |
| `material` | `종이팩` / `비닐류` / `종량제` / `대형폐기물` … | str | 심어 둠 — 필터 · Self-Query 는 이번 범위 밖(README 6번 개선 방향). FAQ 에는 없음 |
| `item` | `선글라스` | str | **출처 표기** — «📚 안경·선글라스 · 사례집(2026) p.31» |
| `section` | `3.1 종이류` | str | 본문 청크의 출처 표기 (목차로 만든 쪽 → 소절 표) |
| `qa_date` | `2025-06-21` | str | 사례가 언제 답변된 것인지 (사례집만) |
| `chunk_id` | `57` | int | 운영 · 디버깅 · 평가에서 같은 청크 합치기 |
| `splitter` | `qa-unit` / `faq-unit` / `item-line` / `page→recursive-400-40` | str | ★ 분할 전략 A/B 비교 (실제 적용된 것만 기록) |

- **설계 원칙 3가지(2교시 2-3)를 어떻게 지켰나**
  1. *나중에 복원할 수 없는 것 우선* → `page` · `item` · `qa_date`. 자르고 나면 «이 문장이 몇 쪽 어느 품목이었는지» 를 알 수 없습니다.
  2. *필터로 쓸 값은 타입을 맞춘다* → `year` 는 **숫자** `2026` (문자 `"2026"` 이면 `year >= 2020` 범위 필터가 깨짐).
  3. *본문에 이미 있는 것은 안 넣는다* → 배출 방법(«종량제봉투로 배출») 자체는 메타데이터로 빼지 않습니다. 본문에 있습니다.
- 값이 없는 키는 **넣지 않습니다**(`None` 금지 — 10주차 `build_index.py` 와 같은 규칙). 예: 가이드라인 청크에는 `qa_date` 가 없음.
- `material` 은 사람이 분류하지 않습니다 — 사례집은 **장 이름**(종이·종이컵 / 비닐류 … 12개)을 그대로,
  품목사전은 **배출방법 문구**(«종량제봉투로 배출» → `종량제`, «고철로 배출» → `고철`)를 규칙으로 바꿔 씁니다.
  ⚠️ 품목사전 쪽 끝에 몰려 있는 구분 마크(«고 철 / 가전제품 / 대 형 …»)는 다단 때문에 품목과 줄이 안 맞아 **쓰지 않습니다**(실측).

## 처리 흐름

```
슬랙 @멘션/DM ─▶ 모드 파싱 ─▶ ① 검색 (FAISS · KURE-v1)        ─▶ ② 생성 (A.X 4.0 Light)          ─▶ 슬랙 스레드
"@버릴지도      (검색/비교/      후보 10개 → 2026 문서 거리 −0.09   <근거> 구분자 + «지시가 아니다»     답 + 📚 근거
 아이스팩?"      질문)            → 상위 3개                         근거에 없으면 «찾지 못했습니다»     «아이스팩 · 가이드라인(2018) p.31»
```

- **처리 방식: RAG** — MCP 는 쓰지 않습니다.
  - 고른 이유: 답이 **고정된 공식 문서**에 있고, **«어디에 그렇게 쓰여 있나»(출처)** 가 핵심입니다(1교시 «출처 추적이 결정적인 이유»).
    분리배출은 틀리게 알려 주면 재활용이 안 되므로 근거 없는 답은 쓸 수 없습니다.
  - 파인튜닝이 아닌 이유: 분리배출 기준은 **바뀝니다**(2018 가이드라인 → 이후 투명페트병 별도 배출 → 공동주택 종이팩 분리배출 제도). 문서만 갈아 끼우면 됩니다(1교시 1-2).
- **검색 전략**: 기본 유사도 검색 + `year` 보정 (실측으로 채택 · 부록 D)
  - 사람은 «뽁뽁이» 라고 묻고 문서는 «에어캡» 이라고 씁니다. «돌돌이» ↔ «테이프크리너», «아이스팩» ↔ «냉동팩».
    이 **동의어 간극**을 줄이려고 MultiQuery(질문을 여러 표현으로 다시 써서 검색)를 구현해 비교했지만,
    KURE-v1 + 구조 분할만으로 생활용어 8문항이 이미 모두 풀려 있었고 MultiQuery 는 오히려 낮았습니다(Top-3 23 → 20~21) → **채택하지 않음**.
  - `year >= 2020` 청크의 거리에서 0.09 를 빼 **2026 사례를 앞세웁니다**(필터가 아닌 재정렬 — 2018 에만 있는 품목을 잃지 않게).
- **분기 · 순환**: 필요 없음 → **LCEL** (`retriever | prompt | llm | parser`). LangGraph 는 쓰지 않습니다.
- **봇 골격**: 10주차 `slack_bot_mode/` 를 그대로 출발점으로 — `rag_backend.ask()` 의 **두뇌(문서·분할·모델)만** 바꿉니다.
  `검색` · `비교` 모드도 그대로 살립니다(«RAG 없이 vs RAG 로» 를 슬랙에서 바로 보여 줌).

    검색어 대신 답 문장(«마트 영수증은 종이류로 분리배출해야 합니다.») 을 쓰기도 했습니다. 코드는 남겨 두었습니다(`--strategy multiquery`).
